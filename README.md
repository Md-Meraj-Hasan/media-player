# Professional Local Media Player

Premium dark offline-first MP3 and video player built with HTML, CSS, JavaScript and Capacitor.

## First screen
- Welcome title: **Professional Local Media Player**
- Choice buttons: **Choose MP3 Player** and **Choose Video Player**
- Privacy message: **No internet. No ads. No tracking.**

## Privacy and internet blocking
- No ad SDKs, analytics SDKs, external fonts, remote images, or streaming URLs are included.
- The app is designed to use files selected locally from the device.
- The GitHub Actions workflow applies an Android manifest merger rule to remove the Android `INTERNET` permission, then builds the APK.
- The build workflow verifies that the explicit permission-removal rule is present.

Removing Android's `INTERNET` permission is the platform-level block for ordinary app network access. If you add third-party plugins later, review their permissions and verify the merged manifest before distributing a release.

## Run in a desktop browser
Install Node.js 22 or newer, then:

```bash
npm install
npm run start
```

Open the local URL shown by Vite. Browser media formats depend on the browser and operating system.

## Build APK using GitHub
1. Create a new GitHub repository.
2. Upload these project files and push them to the `main` branch.
3. Open **Actions** in the repository and run **Build Offline Android APK** (or let the workflow run after a push).
4. Open the completed workflow run and download the `meraj-media-player-debug-apk` artifact.
5. Extract the artifact ZIP to get `app-debug.apk`.

The first Android build is generated by the workflow, so the `android/` directory is intentionally generated during the build and excluded from source control.

## Current prototype notes
- The file picker accepts any file type; actual playback depends on Android WebView/browser codecs.
- Select multiple local audio/video files in a session.
- Audio playback has custom play/pause, previous/next, seek, and a session playlist.
- Video uses the device WebView's native playback controls, including fullscreen when supported.
- Supports low-resolution through HD/4K files when the device and codec can decode them; playback is not guaranteed for every container/codec. Very high-bitrate or unsupported formats may stutter or fail.
- Selected files and playlists are session-only; the app does not persist or upload media.
- Background audio playback, lock-screen controls, media notifications, and a persistent library are not included in this first prototype yet.


## Automatic format detection / native playback
- The UI does not ask the user to select a format: users select files and playback chooses a decoder automatically.
- The browser player uses HTML media support for formats the Android WebView can decode.
- `android-native/` contains a starter Android Media3/ExoPlayer plugin for automatic native format detection and playback. It is not yet registered/wired into the current build workflow and has not been device-tested.
- For production native playback, integrate/register the plugin, add the Media3 dependencies, and update the file picker to provide Android content URIs (via a native file picker/document provider). Then test common codecs and error handling on the target Android devices.
- Even with native playback, support depends on available decoders and bundled extensions. Some formats may require additional decoder libraries; no player can guarantee every possible format or every 8K/high-bitrate file.


## Added audio library controls
- Shuffle on/off with a visible scope selector: current folder or all songs.
- Repeat modes: off, repeat all, repeat one.
- Playback speed from 1.0x to 2.0x in 0.1x steps.
- Favorites are saved locally in browser/WebView storage.
- All songs and Favorites views.
- Folder import uses the browser's directory picker (`webkitdirectory`) where supported. The Android WebView's folder selection behavior must be tested on a device; full recursive access to all phone folders requires a native Android document-tree picker and persisted URI permissions.
- This version's audio folder listing is based on folders explicitly imported by the user, not a silent scan of the entire device. Android intentionally restricts unrestricted storage scanning.

## First-run media permission

A native permission bridge starter is provided in `android-native/MediaPermissionPlugin.kt`, with integration notes in `android-native/MEDIA_PERMISSION_SETUP.md`. The intended flow asks for media access on first launch and skips the dialog on later launches while permission remains granted. This bridge is not registered in the generated APK yet; Android integration and device testing are still required. Android may ask again if permission is revoked or app data is reset.
